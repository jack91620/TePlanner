# TePlanner — guide for Claude Code

A trip-planner iOS app delivered as a Swift Package: an `executable` app
target plus a `library` (`TePlannerKit`) that holds all UI/logic. Tests
live against the library so they don't need the full app to run.

## Layout

```
Sources/
  TePlanner/         # @main entry; depends on TePlannerKit
    TePlannerApp.swift
  TePlannerKit/      # all UI, view models, services, models — public API
    ContentView.swift
    MapView.swift
    Models/          # RouteModels.swift
    Services/        # APIService.swift, APIServiceProtocol.swift
    ViewModels/      # ContentViewModel.swift
    Views/           # ItineraryView.swift
Tests/
  TePlannerTests/    # XCTest, depends only on TePlannerKit
```

Anything new that needs a unit test goes in `TePlannerKit`, not
`TePlanner`. Types referenced from the app target (or tests) must be
`public`.

## Build & test (always use `make`, never invent commands)

```
make build       # swift build (macOS host) — fastest sanity check
make build-ios   # xcodebuild for iOS Simulator
make test        # swift test on macOS
make test-ios    # xcodebuild test on iOS Simulator
make test-all    # both
make doctor      # toolchain + simulator diagnostics
make clean       # wipe .build and .derivedData
```

Override the simulator: `make test-ios SIMULATOR='iPhone 16 Pro'`.

Schemes (auto-generated by SPM):
- `TePlanner-Package` — the only scheme that runs tests on iOS.
- `TePlannerKit` — library only, no test action.
- `TePlannerApp` — the app, no tests.

## Conventions

- Swift 5.9+ tools, deployment target iOS 17 / macOS 14.
- SwiftUI + Combine. View models are `@MainActor ObservableObject`.
- Services are protocol-first (`APIServiceProtocol`) so tests can inject
  mocks (`MockAPIService`).
- New shared types in `TePlannerKit` should be `public` if the app or
  tests reference them — past commits had to retroactively add `public`
  for this reason (see `7ab4e07`). Default to `internal` only when the
  type is genuinely private to the library.
- No comments unless the *why* is non-obvious. No emojis in code.

## Known gotchas

- `MapView.swift` uses `MapMarker`, deprecated in macOS 14 / iOS 17.
  Don't "fix" the warning without also updating `MapView.swift`'s
  callers — the new `Marker` API is non-trivially different.
- If `swift build` fails with `PCH was compiled with module cache path
  '/Users/.../TePlanner/.build/...'` — the repo was previously at a
  different path. Run `make clean`.
- Do not touch `.swiftpm/xcode/xcuserdata/` or `*.xcuserstate`. They are
  Xcode-local UI state and are gitignored.

## Verifying UI changes

CLI build/test won't catch SwiftUI layout bugs. After a UI change:

1. `make sim-boot` — boots the simulator and opens Simulator.app.
2. In Xcode: ⌘R to run `TePlannerApp`. (Xcode is the only easy way to
   actually launch the app on the simulator; xcodebuild can build and
   install but the app entitlements/launch flow is fiddly from CLI.)
3. `make sim-screenshot` — saves a PNG to `tmp/screenshots/`. The user
   can paste this back into the conversation.
4. `make sim-log` — streams iOS logs filtered to `TePlannerApp`.

## Test strategy

Default to `make test` (macOS host) — fastest, no simulator boot, covers
all view-model and service logic. Use `make test-ios` only when the
change touches SwiftUI views, Maps, or other iOS-only APIs.
